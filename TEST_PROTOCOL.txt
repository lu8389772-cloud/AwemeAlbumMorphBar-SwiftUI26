AwemeLiquidBar 1.0.52q test protocol

A. Other-profile fullscreen / right actions
1. Enable the third-party fullscreen playback tweak.
2. Enter another user's profile and open a video.
3. Repeat 10 times: open comments -> close comments.
4. Confirm like/comment/favorite/share and avatar remain present after close.
5. Swipe 10 videos and repeat comment open/close on several items.
6. Confirm nickname/caption does not drop to the physical bottom edge after comment dismissal.

B. Clean screen
1. On a normal playable feed, open the avatar menu and choose 一键清屏.
2. Expected: status bar, top chrome, captions/labels, right actions/avatar, progress/speed chrome where controlled by the interaction controller, and LiquidBar disappear.
3. Swipe vertically 5–10 items. Paging must remain normal.
4. Tap the former avatar location once. Expected: only avatar reappears; no other chrome returns.
5. Tap the revealed avatar and choose 退出清屏. Expected: normal chrome and status bar recover.
6. Enter clean screen again, reveal avatar, swipe once. Expected: avatar hides again for the new item and the invisible recovery target follows the new avatar position.

C. Regression
1. Home -> comments -> close comments: right actions remain stable.
2. Friends: bottom bar and caption spacing unchanged outside clean screen.
3. Avatar menu: 进入主页 and download/copy items still work.
4. Messages/Friends unread badges remain unchanged from 1.0.52o.

1.0.52q targeted regression checks
- GitHub Actions must reach the package stage without `_OBJC_CLASS_$_AWEPlayInteractionViewController` undefined-symbol errors.
- Clear all unread Messages. The LiquidBar Messages tab must have no red circle at count 0.
- Generate one or more unread Messages. The numeric badge must appear, then disappear again after the count returns to 0.
- Friends red-dot/numeric reminder behavior must remain unchanged.
